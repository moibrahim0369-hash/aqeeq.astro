# Karmic tail report: delivery, lock and payment (27 November 2026)

## What the page does
`#karmic` shows the three numbers and the edit/save banner (unchanged), then the report as rows (`assets/js/karmic-sheet.js`, styled by `assets/css/y27-compact.css`, generated by the same script as the 2027 report).
- Rows = the real sections of the matching report, plus a free "opening" row. Each row opens an animated popup.
- Free teaser = the opening words of the section, word for word from the report (`assets/data/karmic-previews.json`, built by `node scripts/build-karmic-previews.js` from `karmic-reports/final/*.md`). The file is public on purpose and holds only titles, a one-line hook and a short excerpt per section.
- Not signed in / not bought: blurred rest + "open my full report" (starts the existing karmic checkout).
- Pending: "under review" with a check button; the page re-checks about every minute.
- Rejected: a retry note with the WhatsApp link.
- Approved: every row opens the full text; a "save PDF" button opens a printable page.
- A birth date whose triad has no report yet shows "report in preparation" and no buy button (and the database refuses the order too).

## Server side
- `karmic_content` (private table, service role only): the 26 report texts, loaded from the repo files (byte-identical, md5 checked).
- `karmic_orders`: ties a manual payment to one birth date.
- `karmic_triad(date)`, `karmic_code_for(date)`: the matrix rule of `matrix-method-adapter.js` (triad D, D3, D2) and the exact-then-reversed report lookup of the site loader.
- `karmic_submit(product, method, reference, date)`: replaces `submit_manual_payment` in `karmic-checkout.js`; refuses dates without a report and duplicate pending/approved orders for the same date.
- `karmic_status(date)`: none | pending | approved | rejected for the signed-in user.
- `karmic_access(date)`: the order id when an approved, paid order with an active entitlement exists for that user and date.
- Edge function `karmic-api` (`supabase/functions/karmic-api/index.ts`): needs a signed-in JWT and `karmic_access` (or `is_app_admin`), returns the parsed report; 401/403 otherwise.
- Owner approval is unchanged (`#admin-pay`, `admin_review_manual_payment`).

Migration: `supabase/migrations/20261127130000_karmic_access.sql` (a later `create or replace` fixed a bigint cast in `karmic_triad`; the file already contains the fix).

## Coverage of the 26 triads (27 November 2026)
The matrix produces 26 different triads. The 26 reports of the first batch covered only 20 of them. Six reports were written for the missing triads, in the exact order the matrix produces (base, middle, top): `10-13-3`, `13-7-21`, `17-5-6`, `20-8-6`, `21-3-9`, `8-5-15`. Now all 26 triads have a report: 11 exact and 15 through the reversed code. When the reversed code is used the page says so ("the root in the text is your top number"). Four reports of the first batch can never be produced by a birth date: `12-18-6`, `15-5-20`, `18-10-10`, `6-18-6`.

The six new texts are NOT in the public repository. They live in the private table `karmic_content` and in the git-ignored folder `.private/karmic-final/` on the machine that wrote them (the build script reads that folder too). They follow the same rules as `karmic-reports/final/README.md` and pass its checks, with 2,300 to 2,500 words each (the README asks for 2,600 to 3,200).

## Public copies of the paid texts (must be removed)
`karmic-reports/final`, `karmic-reports/out` and `karmic-reports/pdf` are committed in a public repository served by GitHub Pages, so anyone can download a report without paying (for example `/karmic-reports/pdf/karmic-tail-12-16-4.pdf`). The private table makes the page itself safe, but these files must leave the repository (and its history) before the lock means anything. To add or change a report: edit it outside the public tree, upload it to `karmic_content` (same `code`), then rerun `scripts/build-karmic-previews.js` from a private copy of the texts.
